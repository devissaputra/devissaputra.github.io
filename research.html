System Engineering

Empirical Engineering Design Trade Space: Concrete Slump Experiments

This study uses 103 observed concrete mixture experiments as a systems engineering trade space. It works directly with laboratory alternatives and identifies Pareto efficient choices across cement use, slump, and 28 day compressive strength.

The analysis then changes the decision framing by removing slump as an objective or treating it as an eligibility threshold. This shows how strongly the observed decision set depends on the way engineering requirements are defined.

Data source: UCI Concrete Slump Test, 103 laboratory mixture experiments, DOI 10.24432/C5FG7D.

System Engineering

Requirements Classification Evidence Triage on a Gold-Standard Benchmark

This study evaluates fine grained requirements classification on 571 eTour requirement elements and asks a second systems engineering question: where should limited human review effort be directed when classification errors are unevenly distributed?

The analysis keeps gold aware diagnosis separate from deployable triage. Gold labels define an oracle ceiling, while the operational queue is ranked only from automatic prediction patterns. This exposes both the opportunity for targeted review and the large gap between knowing where errors are and identifying them without the answer key.

Data source: eTour gold-standard requirements benchmark and pinned NoRBERT/FTLR replication artifacts hosted through Zenodo.
Repository Report MD Paper Data source
System Engineering

Forecast Maturity of Technical Performance Margin on NASA Li-ion Battery Aging Data

This study examines how much confidence a decision maker should place in a projected technical performance margin before a requirement boundary is reached. Four NASA lithium ion battery trajectories are monitored at fixed cycle checkpoints so each forecast uses only evidence that would have been available at that decision point.

The analysis tracks current capacity margin, projected crossing of NASA’s 1.4 Ah end of life criterion, forecast revision, and later forecast error. Aggregate error falls sharply as evidence accumulates, but cell level behavior is heterogeneous and one battery produces a false early warning, making forecast stability itself part of the engineering evidence.

Data source: NASA Prognostics Center of Excellence Li-ion Battery Data Set, using cells B0005, B0006, B0007, and B0018.
Repository Report MD Paper Data source
System Engineering

Cross-Project Heterogeneity in Quality-Oriented Engineering Change

This study reanalyzes 2,533 manually classified commits from 54 Apache Java projects to test whether one pooled maintenance profile actually represents individual software systems. Each project is described by its observed mix of perfective, corrective, and other maintenance intent together with project level uncertainty.

The analysis then quantifies cross project heterogeneity, tests its stability as small project samples are removed, and decomposes the result into the project and category combinations that contribute most strongly. The central finding is that a portfolio average can conceal very different local maintenance profiles.

Data source: Trautsch, Erbel, Herbold & Grabowski replication dataset on Zenodo, DOI 10.5281/zenodo.7078179.
Repository Report MD Paper Data source
